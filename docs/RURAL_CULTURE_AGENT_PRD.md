## 1. 产品概述

“乡村文化通”是一款基于 Coze 搭建的乡村文化知识服务 Agent。产品以“熟悉胡家大庄村文化的本地村民”为角色，通过自然语言对话，为用户提供村史、民俗、传统建筑、村落花雕和文化保护相关的信息与建议，并在有可靠资料时标记信息来源。

产品将分散的乡村文化资料整理为可检索的知识库，通过“问题识别—知识检索—答案生成”工作流，降低乡村文化知识的获取门槛，并减少通用模型回答过于泛化的问题。

## 2. 问题背景

乡村文化资料通常分散在村志、调研材料和口述记录中，普通用户查找和理解的成本较高。直接使用通用大模型还可能出现以下问题：

- 回答缺少具体村庄语境，内容同质化；
- 村史、人物和民俗信息可能被混淆或编造；
- 专业表达较多，不利于普通用户理解和传播；
- 文化保护建议可能脱离当地历史与真实生活方式。

## 3. 产品定位与目标

### 3.1 产品定位

面向胡家大庄村文化查询与传播场景，提供具有本地知识和亲切表达方式的乡村文化 AI 助手。

### 3.2 产品目标

1. 帮助用户快速查询村庄历史、民俗和传统建筑知识；
2. 将分散资料沉淀为可检索、可维护的乡村文化知识库；
3. 通过本地化角色和通俗表达提升文化内容的可读性；
4. 对资料不足、存在争议或超出能力范围的问题明确说明边界。

### 3.3 当前非目标

- 不替代村志、档案和专业历史研究；
- 不对存在争议的历史信息给出唯一结论；
- 不代替文保、建筑等专业人员制定实施方案；
- 不处理与胡家大庄村文化无关的通用任务。

## 4. 目标用户

| 用户 | 主要需求 |
| --- | --- |
| 游客与普通访客 | 快速了解村庄历史、民俗和代表性文化内容 |
| 本村居民与年轻群体 | 学习、查询并传播家乡文化 |
| 学生与调研人员 | 获取文化调研的基础资料和研究线索 |
| 设计及文旅从业者 | 了解在地文化背景，获得初步设计或保护思路 |

## 5. 核心使用场景

### 5.1 村史查询

用户询问村庄由来、地名来源、历史变迁和代表人物，Agent 基于知识库提供结构化回答。

### 5.2 民俗介绍

用户询问节庆、饮食、方言和传统习俗，Agent 解释其内容、形成背景和当代意义。

### 5.3 传统建筑解读

用户询问村内传统建筑或空间，Agent 从建筑特征、使用功能和文化含义三个层面进行介绍。

### 5.4 文化保护建议

用户提出文化展示、空间改造或活动策划问题，Agent 基于已有资料给出原则性建议，并提示结合实地调研和专业意见。

### 5.5 知识边界处理

当知识库没有依据、资料存在冲突或问题超出服务范围时，Agent 明确说明信息不足，并引导用户补充问题或资料。

## 7. 核心对话流程

1. 用户输入乡村文化相关问题；
2. Agent 识别问题类型与服务范围；
3. 调用 question 工作流检索乡村文化知识库；
4. 根据问题类型选择对应的回答结构；
5. 检索结果充分时生成答案并标记实际引用来源；
6. 图片或资料未命中时明确说明，不补造链接、数字或出处；
7. 资料不足或存在冲突时说明信息边界；
8. 结合上下文处理用户的进一步追问。

## 8. 功能需求

| 模块 | 功能要求 | 验收标准 |
| --- | --- | --- |
| 文化问答 | 支持村史、民俗和传统建筑等自然语言查询 | 回答与问题相关，优先使用知识库内容 |
| 问题识别 | 区分事实查询、文化解释、建议和越界问题 | 不同问题进入对应回答策略 |
| 知识检索 | 从乡村文化知识库获取相关资料 | 不随意补充无依据的人物、年份和事件 |
| 回答生成 | 按固定结构组织回答 | 重点清楚、篇幅适中、语言易懂，不展示内部推理过程 |
| 来源标记 | 对知识库命中的事实标记实际资料来源 | 来源名称与检索内容一致，不生成无法核验的出处 |
| 多轮对话 | 结合上下文理解指代与追问 | 用户无需重复完整背景即可继续交流 |
| 边界处理 | 处理知识未命中、资料冲突和无关问题 | 明确说明限制，不编造答案 |
| 建议生成 | 提供文化保护与设计方向参考 | 区分事实与建议，明确专业决策边界 |

## 9. Agent 方案

### 9.1 技术与能力组成

| 模块 | 方案 |
| --- | --- |
| 搭建平台 | Coze |
| 运行模式 | 自主规划模式 |
| 大语言模型 | DeepSeek |
| 知识能力 | 乡村文化知识库 |
| 任务编排 | question 工作流 |
| 交互方式 | 自然语言多轮对话 |

### 9.2 角色设定

Agent 被设定为熟悉胡家大庄村文化的本地村民：

- 使用亲切、自然、通俗的表达方式；
- 优先回答与胡家大庄村直接相关的内容；
- 对地方词语和文化背景提供必要解释；
- 不以本地人身份虚构亲身经历；
- 对文化保护和设计问题保持审慎。

### 9.3 回答策略

| 问题类型 | 回答结构 |
| --- | --- |
| 村史事实 | 直接结论 → 历史背景 → 信息边界 |
| 民俗解释 | 民俗内容 → 形成背景 → 当代意义 |
| 建筑解读 | 建筑特征 → 使用功能 → 文化含义 |
| 保护建议 | 问题判断 → 建议原则 → 注意事项 |
| 资料不足 | 明确未知 → 提供已知线索 → 建议补充资料 |
| 图片查询 | 返回已检索到的图片 → 图片未命中时明确提示 |
| 需要引用 | 回答核心事实 → 标记实际来源 → 说明信息边界 |
| 领域外问题 | 说明能力范围 → 引导至乡村文化主题 |

## 10. 知识库设计

| 知识类别 | 内容 | 关键字段 |
| --- | --- | --- |
| 村史 | 建村沿革、地名来源、重要事件 | 来源、时间、可信度 |
| 人物 | 代表人物、传承人及人物故事 | 姓名、关系、出处、公开状态 |
| 民俗 | 节庆、饮食、礼俗和地方表达 | 时间、适用范围、资料来源 |
| 建筑 | 民居、街巷和公共空间 | 名称、年代、位置、保护状态 |
| 非遗技艺 | 手工艺、表演和生产技艺 | 传承方式、代表人物、当前状态 |
| 保护资料 | 调研材料、规划与保护建议 | 作者、年份、适用边界 |

知识库按照主题拆分资料，并保留来源、时间和可信度。多份资料存在矛盾时，保留不同说法，不直接合并为唯一结论。

## 11. Prompt 设计

Prompt 由角色、任务、回答规范和能力边界四部分组成：

1. 明确 Agent 的本地村民角色与服务范围；
2. 要求回答优先依据知识库检索结果；
3. 禁止编造人物、年份、地点和民俗来源；
4. 将事实介绍与建议内容分开表达；
5. 资料不足时主动说明，不强行生成答案；
6. 建议类问题只提供原则与思路，不代替专业判断；
7. 控制回答篇幅，保持亲切、清楚并支持继续追问；
8. 只输出面向用户的最终答案，不展示分析、规划或内部推理过程；
9. 引用必须来自实际检索结果，不虚构来源、年份、数量和机构；
10. 图片资源未命中时明确说明，不生成不存在的图片地址。

## 12. 异常与降级策略

| 异常 | 产品处理 |
| --- | --- |
| 知识库未命中 | 说明暂未找到可靠资料，并提示可补充的资料类型 |
| 资料内容冲突 | 展示不同说法及来源，不擅自确定唯一答案 |
| 用户问题模糊 | 追问地点、时间、人物或具体目标 |
| 用户询问领域外内容 | 说明服务范围并引导至乡村文化主题 |
| 用户要求专业实施方案 | 提供原则性建议，提示咨询相关专业人员 |
| 回答过长或偏题 | 使用固定结构重新组织，优先回答核心问题 |
| 内部推理过程外显 | 通过 Prompt 与输出检查仅保留最终答案 |
| 引用来源不充分 | 删除无法核验的出处与具体数字，提示资料待核实 |
| 图片资源未命中 | 明确说明暂无法展示，并提供可继续查询的资料线索 |
| 角色表达漂移 | 重新加载角色与回答规范，避免退化为通用文化助手 |

## 13. 产品取舍

### 为什么选择对话式 Agent

乡村文化问题具有表达口语化、追问频繁和知识关联性强的特点。对话式交互比传统目录检索更适合普通用户，也能通过追问帮助用户逐步明确需求。

### 为什么限定到具体村庄

垂直范围越明确，知识库越容易维护，也能减少通用模型把其他地区文化错误套用到本村的问题。

### 为什么不直接输出完整专业方案

文化保护和建筑改造涉及现场条件、法规及专业判断。Agent 只提供信息和原则性思路，避免对用户形成错误决策引导。

## 14. 风险与边界

- 口述资料可能存在不同版本，需要标注来源与时间；
- 模型可能把通用乡村知识错误套用到胡家大庄村；
- 人物关系、家庭信息和具体位置可能涉及隐私；
- 未经专业核实的保护与设计建议可能产生误导；
- Coze、模型或知识库配置变化可能影响回答质量。

涉及个人信息时，只使用已公开或获得授权的资料；敏感人物和位置不进入公开知识库。

## 16. 当前版本验证与迭代重点

基于新版在线 Demo 的典型问答复核，当前版本已经能够围绕胡家大庄村的村史、传统建筑和村落花雕进行知识库问答，并支持本地化表达、来源标记与资料未命中提示。现阶段重点处理以下 Bad Case：

- **角色一致性：**个别回答可能从“胡家大庄村村民”退化为通用文化助手；
- **输出可读性：**部分回答会外显分析与规划过程，需要仅保留最终答案；
- **事实可核验性：**年份、数量、机构等具体信息必须与知识库原文逐项核对；
- **引用完整性：**引用名称需要对应实际检索资料，不能使用泛化或推测性来源；
- **多模态资源：**图片未命中时明确提示，不生成不存在的图片链接。

上述问题将作为后续固定测试集的重要类别，通过 Prompt 约束、知识库清洗、回答后处理和人工抽检持续迭代。
