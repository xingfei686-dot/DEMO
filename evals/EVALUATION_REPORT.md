# GoTrip 旅行规划模型评测报告

> 测试日期：2026-10-13
>
> 测试对象：当前线上基线 Prompt（V1）与优化 Prompt（V3）
>
> 样本规模：30 条固定测试用例；开发集 20 条，隐藏集 10 条

## 1. 评测目标

验证旅行规划模型在以下五个维度的表现：

1. 结构完整性：能否输出合法 JSON、正确天数、连续日期、每项必需字段及合理活动数量；
2. 预算符合度：所有活动的人民币合计费用是否不超过活动餐饮预算；
3. 地点真实性：地点是否可信、属于目标城市，是否存在明显幻觉；
4. 路线合理性：同日地点是否集中，是否存在明显折返或不合理跨区；
5. 天气适配度：是否结合逐日天气安排室内外活动，并在恶劣或未知天气下提供提醒或备选。

测试集覆盖基础规划、低预算、恶劣天气、老人/亲子/无障碍等特殊需求，以及长行程、冷门目的地、晚到早走等边界场景；每类 6 条。

## 2. 评测方法

- 结构完整性、预算符合度：由脚本确定性校验；
- 地点真实性、路线合理性、天气适配度：按统一 Rubric 进行 0–2 分辅助评审，并对 10 条隐藏集人工复核；
- 可用行程：结构必须满分，总分至少 8/10，且五个维度均不得为 0；
- 每个版本、每条用例仅生成一次。本结果适合作为本轮产品迭代证据，不等同于有统计置信区间的线上稳定性结论；
- 本轮没有接入地图 POI 与实时路线 API，因此“地点真实性”和“路线合理性”仍属于模型辅助评审，不是地图事实校验。

## 3. 全量 30 条结果

| 指标 | V1 基线 | V3 优化 | 变化 |
|---|---:|---:|---:|
| 请求成功率 | 100.0% | 100.0% | 持平 |
| JSON 解析成功率 | 83.3% | 96.7% | +13.4pp |
| 结构化输出成功率 | 73.3% | 93.3% | +20.0pp |
| 预算符合率 | 66.7% | 73.3% | +6.6pp |
| 天气适配平均分（满分 2） | 1.53 | 1.57 | +0.04 |
| 地点真实性平均分（满分 2） | 1.43 | 1.30 | -0.13 |
| 路线合理性平均分（满分 2） | 1.33 | 1.07 | -0.26 |
| 可用行程率（辅助评审） | 53.3% | 56.7% | +3.4pp |
| 综合平均分（满分 10） | 7.20 | 7.40 | +0.20 |

结论：V3 对输出稳定性和预算约束有效，但没有同时提升地点与路线质量。不能据此宣称五个维度均已提升。

## 4. 隐藏集结果

| 指标 | V1 基线 | V3 优化 |
|---|---:|---:|
| JSON 解析成功率 | 80%（8/10） | 100%（10/10） |
| 结构化输出成功率 | 80%（8/10） | 100%（10/10） |
| 预算符合率 | 60%（6/10） | 80%（8/10） |
| 可用行程率（辅助评审） | 50%（5/10） | 80%（8/10） |
| 综合平均分 | 6.80 | 8.30 |

人工复核发现 V3 的 `SPECIAL-06` 虽被辅助评审判为可用，但用户第一天 22:00 才抵达，行程却从 10:00 开始，属于关键约束冲突。因此隐藏集 V3 的保守可用率按 7/10，即 **70%** 记录。用于简历时建议写“隐藏集可用行程率由 50% 提升至 70%”，并能在面试中解释这一人工降级。

## 5. 主要 Bad Case

### 已改善

- JSON 被截断或引号转义错误：通过限制字段长度、要求紧凑 JSON、生成前自检，解析成功率由 83.3% 提升到 96.7%；
- 币种和人数口径不清：统一要求费用为全部旅客合计人民币；
- 雨天仍安排高风险户外活动：加入逐日天气约束与恶劣天气室内优先规则；
- 低预算场景超支：加入费用汇总上限和免费地点优先规则，预算符合率有所提升。

### 仍未解决

- 硬约束遗漏：晚到早走、预约时间、老人步行强度等仍可能被忽略；
- 路线幻觉：模型会写出“步行 10 分钟”等未经验证的距离，或把跨区地点排在同一天；
- 长行程重复：7 天用例出现多个地点反复安排；
- 预算仍会失守：30 条中仍有 8 条未达到满分预算合规；
- Prompt 过度压缩的副作用：文本更短、JSON 更稳定，但地点信息和路线解释变少，导致地点与路线平均分下降。

## 6. 下一轮产品方案

1. 在生成前把用户输入转换为机器可校验的约束表，包括抵离时间、人数、预算、无障碍与每日天气；
2. 在生成后增加 JSON Schema、总费用、天数、活动数和抵离时间的确定性校验；
3. 接入高德 POI 搜索与路径规划，对地点存在性、城市归属、通勤距离做事实校验；
4. 若校验失败，只重写失败日期，而不是重新生成全部行程；
5. 对模型输出做 3 次重复测试，报告均值与波动，避免单次采样偶然性。

## 7. 简历建议表述

> 模型评测与迭代：建立 30 条旅行规划测试集，按基础规划、预算、天气、特殊需求及边界场景分层，并以 20/10 划分开发集与隐藏集；从结构完整性、预算符合度、地点真实性、路线合理性和天气适配度五个维度建立评测 Rubric。针对 JSON 截断、预算超支、地点幻觉和天气约束遗漏等 Bad Case 优化 Prompt 与降级策略，使结构化输出成功率由 73.3% 提升至 93.3%、预算符合率由 66.7% 提升至 73.3%，隐藏集可用行程率经保守复核由 50% 提升至 70%。

## 8. 可复现文件

- `cases.json`：30 条固定测试用例；
- `run-evaluation.mjs`：V1/V2 基线评测；
- `run-v3.mjs`：V1/V3 对照评测；
- `evaluation-summary-v3.json`：逐条评分、问题记录与汇总结果。

为避免仓库文档被大体积模型全文占据，公开版本保留逐条评分和问题记录，不收录完整模型回答；本地运行脚本会生成 `raw-results*.json` 供复核。
